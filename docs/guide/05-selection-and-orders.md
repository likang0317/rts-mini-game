# 05 选择、指令与目标点分配

## 现在有什么

`MainScene.ts` 里和"下达指令"有关的只有三处：

- 点选/框选：`applySelection()`（L189-213），点选半径 22px，框选用 `Phaser.Geom.Rectangle.Contains`。
- 目标点分配：`commandMove()`（L230-244），把选中单位排成方阵，每个偏移 34px。
- 执行：`updateUnits()`（L246-264），直线走向 `target`。

能跑，但只覆盖了"移动"一种指令，而且没有队列、没有编队、没有目标类型判断。这一章讲怎么把它扩成一套完整的指令系统——**注意，输入方式要先按第 04 章改成触屏，再回来加指令**。

## RTS 的指令模型：三层

不要一上来写"右键 = 移动"。RTS 的指令应该拆成三层：

```
玩家意图（点了一个敌人）
  → 指令类型（攻击）
    → 参数（目标实体 id）
      → 执行器（走到攻击距离内，按间隔攻击）
```

对应到类型：

```ts
// src/game/sim/orders.ts
export type Order =
  | { kind: 'move'; x: number; y: number }
  | { kind: 'attackMove'; x: number; y: number }
  | { kind: 'attack'; targetId: number }
  | { kind: 'gather'; nodeId: number }
  | { kind: 'build'; buildingId: number; x: number; y: number }
  | { kind: 'stop' };

export interface OrderQueue {
  current: Order | null;
  pending: Order[];      // 最多 4-5 条，多了玩家也记不住
}
```

**为什么不用一个 `target: Vector2` 打天下**：因为攻击要追一个会动的实体，采集要循环往返，建造要等资源到位。这些都不是"一个坐标"能表达的。现在的 `Unit.target`（`MainScene.ts:16`）在只有移动时够用，加第二种指令就会开始塞 `if`。

## 没有右键，怎么表达"对目标下令"

桌面的右键是"动词 + 目标"一次完成。手机上的替代方案是**上下文指令**：玩家只点目标，系统根据目标类型决定动词。

| 点到的对象 | 默认指令 | 备注 |
| --- | --- | --- |
| 敌方单位 | 攻击 | 不需要先按"攻击"按钮 |
| 资源点 | 采集 | 农人才有效，兵点了变成移动 |
| 己方建筑 | 选中建筑 / 打开面板 | 不是移动 |
| 中立部落 | 交涉（或攻击，需长按） | 默认不打，避免误掉德望（`DESIGN-v2.md:5.3`） |
| 空地 | 移动 | 唯一需要"确认感"的指令 |

这套映射的好处是**手指只需要点一次**。坏处是**歧义**：敌军站在资源点旁边，你点下去到底打还是采？

处理办法：**先做命中测试，按优先级取目标**——单位 > 资源点 > 建筑 > 地面。然后再看目标与当前选中单位的关系（敌方/己方/中立）。命中测试的半径要比视觉大一圈（第 04 章说的 44-48px）。

## 目标点分配：别让 12 个单位叠在一个像素上

`commandMove()` 现在的做法是方阵：

```ts
const columns = Math.ceil(Math.sqrt(targets.length));
const offsetX = ((index % columns) - (columns - 1) / 2) * 34;
const offsetY = (Math.floor(index / columns) - (rows - 1) / 2) * 34;
```

三个问题：

1. **不检查落点是否可走**。偏移后可能落在建筑里、水里、地图外。现在只做了 `Clamp`（L240-241），挡不住建筑占位。
2. **不按距离分配**。`Array.from(this.selected)` 的顺序决定谁去哪个格子。结果是最远的单位可能分到最近的格子，队伍先交叉再散开。
3. **没有队形概念**。方阵适合"站住"，不适合"穿过窄口"。

实用改法（按成本从低到高）：

### 方案 1：贪心就近分配（够用）

1. 生成 N 个目标槽位（方阵或圆形）。
2. 对每个单位，找最近的空槽位，占用。
3. 槽位不可走就向外扩散一圈重找。

```ts
function assignSlots(units: UnitState[], slots: Vec2[], walkable: (x: number, y: number) => boolean): Map<number, Vec2> {
  const free = slots.filter(s => walkable(s.x, s.y));
  const result = new Map<number, Vec2>();
  for (const u of units) {
    let best = -1;
    let bestD = Infinity;
    for (let i = 0; i < free.length; i++) {
      const d = (free[i].x - u.x) ** 2 + (free[i].y - u.y) ** 2;
      if (d < bestD) { bestD = d; best = i; }
    }
    if (best >= 0) {
      result.set(u.id, free[best]);
      free.splice(best, 1);
    }
  }
  return result;
}
```

这是 O(N²)，N < 50 时完全没问题。**不要上匈牙利算法**，收益不值那个复杂度。

### 方案 2：按编队形状分配

- 方形队形：适合站桩防守。
- 楔形/横排：适合正面推进，近战在前、远程在后。
- 纵队：适合穿窄口。

形状由"当前选中单位的兵种构成"决定，不是由玩家选。手机上不要再加一个"选队形"的按钮。

### 方案 3：流场（第 06 章）

当目标点相同、单位数超过 30 时，逐单位 A* 会让所有人挤同一条路。这时用流场：对目标点做一次反向 BFS，得到每个格子的"下一步方向"，所有单位共享。代价是只适合"同一目的地"的群体移动。

## 指令队列：手机上的取舍

桌面用 Shift 排队列。手机没有 Shift，两种做法：

1. **队列开关**：命令卡上有一个「队列」按钮，打开后连续点的指令会追加而不是替换。适合少量操作。
2. **默认替换，长按追加**：点地面 = 立刻移动；长按地面 300ms = 追加到队尾。这个更符合触屏直觉，但需要明确反馈（队尾出现编号小旗）。

**建议 v0.1 只做"替换"**，队列等到有采集回环和建造之后再上。理由：队列的 bug（永远不清空、执行到一半卡住）很难查，而前期玩家一次只会下一两个指令。

队列实现的三个坑：

- **执行完要清空**。`current` 完成时必须从 `pending` 取下一条，不能只把 `current` 置空。
- **新指令要能打断**。玩家点"停止"或点新目标时，队列要整体清掉，不能"排队等死"。
- **目标实体可能已死**。`attack` 指令的 `targetId` 找不到时，要降级为 `move` 到目标最后位置，而不是原地发呆。

## 编队：按钮替代 Ctrl+数字

底部 3-5 个槽位，每个 56×56（第 04 章的手指点按下限）：

- **点击** = 选中该编组。
- **长按 300ms** = 把当前选中写入该编组。
- **双击** = 镜头飞到编组中心。

数据结构就是 `groups: number[][]`，存单位 id，不存对象引用。单位死亡时不用急着清理，选中时过滤掉不存在的 id 即可——**每帧清理反而容易漏**。

```ts
// 选中编组时过滤已死单位
const alive = group.filter(id => state.units.some(u => u.id === id));
```

N 很小时 `some` 足够快；单位上千再换 `Map<number, UnitState>`。

## 选择本身也有优先级

`applySelection()` 现在用"距离最近且在 22px 内"（L196-198），有两个隐患：

- **建筑和单位重叠时**，可能选中建筑，也可能选中单位，取决于数组顺序。
- **框选只判断中心点**（L208），大单位边缘在框内但中心在框外就选不中。

改法：

- 命中测试按"单位 → 建筑 → 地面"分层，每层内部再按距离。
- 框选判断用**包围盒相交**，不是中心点包含。
- 点选半径用世界坐标 24-28px（对应屏幕上 48-56px），并且**随相机缩放反向补偿**：放大时半径缩小，缩小时半径放大，保证屏幕上的手感一致。

## 常见 bug 清单

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 一队兵走到一起后互相推挤、原地抖 | 目标点相同 + 无分离 | 槽位分配 + 局部避让（06 章） |
| 单位走到建筑里 | 只 `Clamp` 没做可走判定 | 落点先过 `walkable()` |
| 下了新指令，老指令还在执行 | 没有清 `current` | 下令即覆盖，队列按规则清空 |
| 攻击指令追到地图另一头 | 没有脱战半径 | 目标超出 acquisition range × 1.5 就放弃 |
| 框选漏单位 | 只判断中心点 | 包围盒相交 |
| 双击编队没反应 | 双击被识别成两次单击 | 记录上次点击时间与槽位，250ms 内算双击 |

## 落到代码：先改哪一段

1. 新建 `src/game/sim/orders.ts`，定义 `Order` 与 `OrderQueue`。
2. 把 `Unit.target: Vector2` 换成 `order: Order | null`（`MainScene.ts:16`）。
3. 把 `commandMove()` 改成 `issueOrder(unitIds, order)`，内部做槽位分配。
4. 输入层只负责"把点击翻译成 Order"，不直接改单位位置。

第 4 条是关键：**输入层永远不应该知道"移动"是怎么执行的**。它只产出意图，仿真层决定怎么做。

## 一句话总结

**指令是"意图 + 目标"，不是"坐标"。** 把这句话落成类型，后面的采集、建造、战斗都能挂上去。
