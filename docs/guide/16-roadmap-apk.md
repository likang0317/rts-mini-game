# 16 分阶段路线：按 APK 重排

## 原则

**每一阶段的终点，都是"手机上能装、能验"。** 不是"代码写完了"，不是"桌面能跑"。

这条原则会砍掉很多你原本想做的事。砍得对：你现在最贵的资源是注意力，不是代码量。

## 阶段总览

| 阶段 | 产出 | 估算 | 关键动作 |
| --- | --- | --- | --- |
| P0 出包 | 能装的 APK，3 个方块 | 1-2 天 | Capacitor、横屏、安全区、DPR |
| P1 地基 | 触屏能选中/移动，逻辑分层 | 3-5 天 | 固定步长、`src/game`、手势状态机 |
| P2 经济 | 采一种资源、造一个建筑 | 1 周 | 地图数据、采集回环、中心准星放置 |
| P3 战斗 | 造兵、互砍、死亡 | 1 周 | 训练队列、战斗结算、索敌 |
| P4 目标 | 祭坛、祭祀、德望、胜负 | 1 周 | 读条、增益、胜利条件 |
| P5 打磨 | 可读、可听、可发布 | 1 周 | HUD、音效、平衡、release 签名 |

总计 **5-7 周**（估算，每天 3-4 小时）。这是"能玩一局"的最短路径，不包含美术替换和战役。

## P0：第一个能装的包（1-2 天）

### 做什么

1. 按第 13 章接入 Capacitor。
2. `vite.config.ts` 加 `base: './'`。
3. 横屏锁定 + `configChanges`。
4. 安全区 CSS 变量。
5. 量一次 canvas 的实际像素（第 13 章那行日志）。
6. `adb install`，在手机上看到三个方块。

### 不做什么

- 不重写输入。
- 不改玩法。
- 不做 UI。
- 不做图标（先用默认）。

### 验收

- [ ] 手机上能启动，断网能玩。
- [ ] 横屏锁定，旋转不重启。
- [ ] 刘海不挡画面。
- [ ] 你知道自己在渲染多少像素。

**这一阶段的价值不是"有个包"，是"打掉桌面幻觉"。** 你会第一次看到：单位只有指甲盖大，文字小到看不清，右键根本不存在。

## P1：地基（3-5 天）

### 做什么

1. **固定步长**：`accumulator` + `SIM_DT = 1/60`（第 02 章）。
2. **逻辑分层**：新建 `src/game/`，`UnitState` / `UnitView` 分开（第 03 章）。
3. **触屏输入**：单指点选、点地面移动、拖空白平移、双指缩放、tap-tap（第 04 章）。
4. **默认 zoom 0.7**，让视野到 20 格以上。
5. **点选半径按屏幕 48px 折算**，不要用世界坐标 22px。

### 砍什么

- **先不做框选**。长按框选是"第二优先级"，先用"点选 + 全选按钮"把链路跑通。
- **先不做编队**。
- **先不做 UI 美化**。

### 验收

- [ ] 单手选中一个单位，让它走到屏幕另一头，连续 10 次不误触。
- [ ] 双指缩放后，单位命中区手感不变。
- [ ] CPU 降速 6 倍，移动速度不变。
- [ ] `src/game` 不 import Phaser 运行时。

## P2：经济（1 周）

### 做什么

1. **地图数据**：`Terrain` + 一种资源点（建议先做**木**，因为往返逻辑最典型）。
2. **采集回环**：走 → 采 → 回 → 卸 → 折返（第 09 章）。
3. **资源 HUD**：顶部一个数字，变化时更新。
4. **建造**：一个建筑（建议**祭坛**），中心准星放置 + 确认/取消（第 04 章）。
5. **占位**：建筑覆盖格标 `Blocked`。

### 砍什么

- 不做四种资源，先做两种（木 + 谷）。
- 不做伐木场/采石场，全部送回大邑。
- 不做建造动画，用进度条代替。
- 不做资源点枯竭，先无限。

### 验收

- [ ] 农人能稳定采木，每趟 +10，不卡住。
- [ ] 资源够时能造祭坛，不够时按钮灰掉。
- [ ] 放置时手指不挡住幽灵建筑。
- [ ] 建筑放下后，单位不会穿过去。

## P3：战斗（1 周）

### 做什么

1. **训练**：大邑造农人/族兵，队列 + 进度。
2. **人口**：上限 12，显示在 HUD。
3. **战斗**：hp、伤害、护甲、攻击间隔、死亡（第 08 章）。
4. **索敌**：范围内自动打，脱战半径。
5. **攻击指令**：点敌人 = 攻击。

### 砍什么

- 不做远程（先只做近战）。
- 不做护甲类型克制。
- 不做技能/祭祀增益。
- 不做 AI，敌人站着不动挨打。

### 验收

- [ ] 3 个族兵打 5 个农人，10 秒内结束。
- [ ] 单位死亡后消失，不"鞭尸"。
- [ ] 攻击间隔稳定，不随帧率变化。

## P4：目标（1 周）

### 做什么

1. **祭祀**：祭坛读条 8 秒，消耗玉，给一个增益（先做祈谷）。
2. **德望**：祭祀 +2，显示在 HUD。
3. **胜负**：摧毁敌方大邑 = 胜；己方大邑被毁 = 负。
4. **结算界面**：一局结束能重开。

### 砍什么

- 不做归附/禅让（第 09 章算过，数值还没调通）。
- 不做四种祭祀，先做一种。
- 不做天气/地形。

### 验收

- [ ] 一局 10 分钟内能分出胜负。
- [ ] 祭祀读条能被打断。
- [ ] 结算后能直接开下一局。

## P5：打磨（1 周）

### 做什么

1. **可读性**：血条按需显示、选中圈、落点反馈（第 11 章）。
2. **音效**：点击、攻击、建造完成，3-5 个就够。
3. **性能**：图集、对象池、降级阶梯（第 12 章）。
4. **发布**：keystore、release 包、覆盖安装测试（第 14 章）。
5. **平衡**：按第 10 章的方法调一轮，记录改了什么。

### 验收

- [ ] 截图缩到 30% 仍能看懂局势。
- [ ] 100 单位 30fps（目标机型）。
- [ ] release 包能覆盖升级。
- [ ] 连续玩 30 分钟不崩。

## 第一个"能装到手机上的可玩包"到底包含什么

如果你只想先做一个东西给朋友看，最小范围是：

- 1 张 40×30 地图。
- 1 个基地、3 个农人。
- 1 种资源（木）。
- 1 个建筑（祭坛）。
- tap 选中、tap 移动、tap 资源采集、中心准星建造。
- 一个资源数字、一个建造进度条。
- **没有战斗、没有敌人、没有胜负。**

它 5 分钟内能走完"选农人 → 采木 → 造祭坛"，这就够了。**它的作用是验证"手机上能不能操作"，不是"好不好玩"。**

## 在此之前，不要做这些

| 不要做 | 为什么 |
| --- | --- |
| 桌面右键/框选/滚轮 | 手机上全部作废，写了就是白写（第 04 章） |
| 美术资源/图集/动画 | 玩法没验证，美术会全部返工 |
| AI | 先让敌人站着不动，确认玩家操作链路通了 |
| 三个阵营 | 一个阵营的数值都还没跑通 |
| 联机/lockstep | 单机都没闭环，联机是另一个项目 |
| 战争迷雾/天气/地形 | `DESIGN-v2.md` 里是 M2/M3 的内容 |
| 300 单位性能优化 | 你连 20 个单位都没跑过（第 12 章） |
| 战役/剧情/关卡编辑器 | 先把一局做好 |
| 设置菜单/存档系统 | 首版不需要 |
| 继续扩写设计文档 | 文档已经够多了，缺的是可运行的东西 |

## 如果决定换引擎

按第 00 章的闸门，只有满足条件才换。换的时候：

1. **冻结玩法**：不改规则，只做移植。
2. **带走数据表**：`src/game/data/*.ts` 导出成 JSON，Godot 直接读。
3. **带走逻辑**：`src/game/sim/*` 按 1:1 重写成 GDScript（状态机、A\*、伤害公式都是语言无关的）。
4. **重写表现**：Godot 的 `Node2D` + `Control`，不要试图复刻 Phaser 的 Scene 结构。
5. **先跑通一条链路**：选中 → 移动 → 采集，再谈战斗。

**不要"边移植边加功能"。** 那是两个项目叠在一起，一定烂尾。

## 自检

- [ ] 你知道当前在哪个阶段。
- [ ] 当前阶段的验收标准全部可观测，没有"感觉差不多"。
- [ ] 你已经砍掉了不属于当前阶段的东西。
- [ ] 每个阶段结束都有一个能装的包。
- [ ] 你能说出"如果明天要给别人玩，我拿什么给他"。

## 一句话总结

**先把"手机上能操作"验证掉，再谈"好不好玩"，最后才谈"好不好看"。** 顺序反了，就是半年后推倒重来。
