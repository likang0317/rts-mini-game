# 11 可读性：让玩家看懂战场

## RTS 真正的难点不是"做出来"，是"看得懂"

即时战略的信息量是所有类型里最大的：

- 你有多少资源、多少人口、多少兵。
- 每个兵在哪、在打谁、还剩多少血。
- 敌人在哪、在干什么、有没有来偷家。
- 你现在选中的是谁、能下什么指令。

**玩家每秒钟只能处理少量信息。** 你的工作不是把所有信息都画出来，是决定"什么时候给他看什么"。

## 信息分三层

| 层级 | 内容 | 显示时机 |
| --- | --- | --- |
| 常驻 | 四资源 + 德望、人口、小地图、选中数量 | 永远 |
| 选中时 | 单位头像/名称、血条、可用指令、编组 | 有选中 |
| 按需 | 详细数值、建筑进度、祭祀剩余时间 | 点开面板 |

现在的 HUD 是一段文本（`createHud()`，`MainScene.ts:151-163`），四行字把所有信息塞在一起。单位少的时候能看，单位一多就是灾难。

**先做分层，再做美化。** 把"常驻"和"选中时"分开，哪怕两边都还是纯文本。

## 血条：不要一直显示

现在每个单位头顶有一个 30×4 的血条（`createUnit()` L102），永远显示。

3 个单位时没问题，100 个单位时：

- 100 条血条 = 视觉噪音，玩家反而看不清战场。
- 每条血条都是一个 GameObject，渲染开销不大，但屏幕会花。

**规则：**

- 满血 + 未选中 → 不显示。
- 受伤 → 显示，颜色随血量变（绿 → 黄 → 红）。
- 选中 → 显示，不管满不满。
- 死亡 → 血条立刻消失（`syncViews` 的删除分支，第 03 章）。

血条宽度不要按像素写死 30，按单位尺寸比例算。手机上看，4px 高的血条在 DPR 2 下等于 8 物理像素，够用；再细就看不清。

## 选中反馈：圈 + 地面标记

选中圈现在的做法是 36×36 的描边矩形（`createUnit()` L100），能用，但有两个问题：

- 单位重叠时，圈也重叠，分不清选中了谁。
- 圈的颜色（`0x7ef2c8`）和单位颜色（`0x4dabf7`）对比度不够。

改进：

- 圈用**椭圆**（俯视角看地面），比矩形更像"站在地上"。
- 选中的单位脚下加一个半透明圆底，多个单位重叠时也能看出范围。
- 敌方/己方用不同的圈形（己方实线、敌方虚线/双线），不要只靠颜色——色盲玩家分不清。

## 指令反馈：让玩家知道"命令收到了"

RTS 里最让人焦虑的是"我点了，但它没动"。

三类反馈，按优先级：

1. **落点标记**：点地面移动后，目标点出现一个 0.4 秒的收缩圆圈。这是最低成本的"收到了"。
2. **路径预览**：只对 1-2 个单位显示 0.3 秒的细线，队伍多了不显示（会糊成一片）。
3. **失败提示**：目标不可达时，单位头顶冒一个"×"或短促的红色闪烁，同时 HUD 出一行"无法到达"。

**不要做**：屏幕震动、全屏闪光、长音效。RTS 一局几百次指令，任何强反馈都会变成骚扰。

## 镜头：手机上不要抄桌面

桌面 RTS 的镜头习惯在手机上几乎全废：

| 桌面 | 手机 | 原因 |
| --- | --- | --- |
| 鼠标移到屏幕边缘推屏 | **不要做** | 手指本来就挡边缘，极易误触 |
| 滚轮缩放 | 双指捏合 | 标准手势 |
| 空格回基地 | 双击基地按钮 / 小地图点基地 | 没有键盘 |
| 惯性滑动 | **不要做** | RTS 需要对位，惯性会让"停在这里"变成"滑过去" |
| 小地图点击跳转 | 保留 | 手指点小地图比拖地图快 |

**默认缩放**：现在 `cam.zoom` 初始是 1（`MainScene.ts` 没设，Phaser 默认 1），开局只能看到 16×7 格（第 07 章算过）。建议初始 `0.7`，让视野到 23×10 格。

## 手机 HUD 布局

横屏，CSS 视口约 800×360。按拇指可达性分区：

```
┌──────────────────────────────────────────────┐
│ 谷 200  木 120  石 80  玉 20   德望 20/100   │ 顶部 0-10%，只看不点
├──────────────────────────────────────────────┤
│                                              │
│                战 场（中间 55%）              │
│                                              │
│  ┌────────┐                                  │
│  │ 小地图  │        ┌──────────────────────┐  │
│  │ 120×90 │        │  命令卡（底部 30%）   │  │
│  └────────┘        │  [耕作][伐木][建造]   │  │
│                    │  [停止][攻击移动]     │  │
│                    └──────────────────────┘  │
└──────────────────────────────────────────────┘
```

三条硬规则：

1. **高频按钮在底部 35-40%**。顶部只放"看"的信息，不放按钮。
2. **所有可点目标 ≥ 44-48 CSS px**，推荐 56。第 04 章已经说过。
3. **留安全区**：`env(safe-area-inset-bottom)`，否则手势条会盖住命令卡（第 13 章给 CSS）。

小地图不要做得太大。手机上 120×90 已经够看趋势，再大就挤占战场。

## 高保真稿是桌面尺寸，不能直接用

`docs/ui/ui-a.html` 那套六状态设计稿是按 **1920×1080** 做的（`docs/ui/UI-SPEC.md` 里有基准说明）。它在桌面浏览器里很好看，但**直接搬到手机上会出两个问题**：

- 按钮尺寸按 1920 宽设计，缩到 800 宽后，原本 64px 的按钮变成 27px，低于手指极限。
- 布局是"左右两侧信息栏 + 中间战场"，手机横屏只有 360 高，两侧栏会把战场压成一条缝。

**处理办法**：把 `ui-a.html` 当作**视觉语言参考**（配色、边框、字体气质），不要当作布局参考。手机 HUD 要重新排：顶部一条资源、底部一张命令卡、左下小地图。这是两份不同的设计，不是"缩放一下"。

这条如果不处理，你会做出一个"电脑上很精致、手机上点不中"的界面。

## 颜色与对比

- **阵营色 + 形状双重编码**。只靠红/蓝区分，色盲玩家（约 8% 男性）会分不清。
- **地形底色要压暗**。现在的地图底色 `0x27362b` 偏暗，单位 `0x4dabf7` 亮蓝，对比够；但以后加资源点、建筑，要保证"单位永远比地形亮"。
- **血条颜色**：绿 `0x5fdc7a` 现在这个值偏亮，在亮地形上会糊。建议加 1px 深色描边。

## 文本：手机上不要小于 14px

现在 HUD 是 14px（`MainScene.ts:155`），在 DPR 2 的手机上物理像素是 28，能看。但：

- 全屏游戏时，玩家离屏幕更远，14px 偏小。
- 建议正文 16px，标题 20px，关键数字（资源）24px。
- 不要用细体（100-300 字重），手机上会发虚。

## 一个残忍但有效的测试

把游戏跑起来，截一张图，**缩到 30%**，然后问自己：

1. 能一眼看出哪边在赢吗？
2. 能看出你的兵在哪吗？
3. 能看出哪个单位快死了吗？
4. 能看出你现在选中了什么吗？

如果四个问题有一个答不上来，说明信息层级不够，而不是"美术不好"。

## 自检

- [ ] 满血未选中的单位不显示血条。
- [ ] 选中 20 个单位时，能看出它们的位置和大致血量。
- [ ] 点地面后 0.4 秒内有落点反馈。
- [ ] 目标不可达时有明确提示，不是"点了没反应"。
- [ ] 开局能看到至少 20×10 格。
- [ ] 所有按钮 ≥ 48px，且不被安全区遮挡。
- [ ] 截图缩到 30% 仍能判断局势。
- [ ] 色盲模式下（或去掉颜色只看形状）仍能分清敌我。

## 一句话总结

**可读性不是"画得好看"，是"玩家不用想就能看懂"。** 每一个像素都在回答一个问题：我现在该干什么。
