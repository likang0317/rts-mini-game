# 04 触屏 RTS 的交互重设计（最重要的一章）

## 为什么这章必须先写

`MainScene.ts:106-149` 里那套输入模型是**桌面思维**：右键下令、拖拽框选、滚轮缩放、Shift 加选、H 回基地。这五件事在手机上**一件都不成立**：

- 没有右键
- 没有悬停（手指按下才算事件，抬起就结束）
- 拖拽被"平移镜头"占用
- 没有滚轮
- 没有键盘（除非做软键盘，那更糟）

如果你先按桌面做完，装到手机上会发现操作链根本走不通，而交互是长在逻辑里的——改它等于重写。所以这一章放在经济、战斗之前。

## 手机 RTS 的四条硬约束

先记住这四条，后面所有方案都是它们的推论。

1. **手指是 9-11mm 的肉垫，不是 1px 的箭头。** 可点击目标最小 44-48 CSS px，推荐 56 px 以上。你现在 `MainScene.ts:197` 的点选半径是 22px，在手机上等于"永远选不中"。
2. **拇指只覆盖屏幕下三分之一。** 高频操作必须放在底部 35-40% 区域，顶部只放"看"的信息。
3. **一次触摸只能做一件事。** 鼠标可以"移动的同时按键"，手指不行。所以每个操作都要串行化、要有明确的状态机。
4. **误触的代价远大于慢。** 桌面点错一下重来；手机上误触移动会让整队兵跑进敌人家里。所有"不可逆"的操作都要二次确认或可撤销。

## 手势方案对照表

先给结论，再解释：

| 桌面操作 | 手机替代 | 优点 | 代价 |
| --- | --- | --- | --- |
| 左键点选 | 单指点单位 | 直觉、零学习 | 小目标难点中，需要放大命中区 |
| 拖拽框选 | **空白处长按 250ms 后拖动** | 保留框选语义 | 与平移抢同一个手势，要有明显进入反馈 |
| 右键下令 | **点选后再点地面（tap-tap）** | 单手、无遮挡 | 容易误触移动，需要"点击空白=取消选中"来兜底 |
| 悬停看信息 | 点选即看 / 长按查看 | 简单 | 看不到就点，节奏变慢 |
| Ctrl+数字编队 | 底部编组槽按钮 | 可见、可点 | 占用 HUD 空间 |
| 滚轮缩放 | 双指捏合 + 双击 | 标准手势 | 双指手势要和小地图/命令卡不冲突 |
| Shift 加选 | 选中后点"加选"开关，或长按单位 | 可控 | 多一步 |
| 键盘快捷键 | 底部命令卡按钮 | 触屏原生 | 按钮数量受限，最多 6-8 个 |

## 我建议的这套（可直接照做）

### 相机

- **单指在空白处拖动 = 平移**。判定阈值 8-10 px：位移小于阈值算"点击"，大于才算"拖动"。
- **双指捏合 = 缩放**，缩放中心取两指中点，范围限死（比如 0.8-1.6），不要让它缩到看不见单位。
- **不要做屏幕边缘推屏**。桌面 RTS 的边缘滚动在手机上极易误触，而且手指本来就挡着边缘。
- **不要做惯性滑动**。RTS 需要精确对位，惯性会让"我明明停在这里"变成"又滑过去半个屏幕"。

Phaser 里必须显式开启多点触控，默认只处理单指：

```ts
// main.ts 的 GameConfig
input: { activePointers: 3 }   // 鼠标 + 双指

// 或者场景内
this.input.addPointer(2);
```

同时把浏览器的默认手势全关掉，否则 Android WebView 会把双指捏合当成页面缩放：

```html
<!-- index.html -->
<meta name="viewport" content="width=device-width,initial-scale=1,maximum-scale=1,user-scalable=no,viewport-fit=cover">
```

```css
html, body, canvas {
  touch-action: none;        /* 关键：交给游戏处理所有手势 */
  overscroll-behavior: none;
  user-select: none;
  -webkit-tap-highlight-color: transparent;
}
```

## 选择：三套方案怎么选

### 方案 A：长按进入框选（推荐）

- 空白处按住 250ms → 屏幕出现"框选模式"提示（边框变色 + 轻微震动 `navigator.vibrate(10)`）
- 继续拖动 → 拉出选框；抬起 → 选中框内单位
- 空白处**快速**拖动 → 平移镜头

优点：保留了"一把框住一队兵"的爽感，这是 RTS 的核心操作。
缺点：需要一个清晰的模式反馈，否则玩家分不清自己在平移还是在框选。

实现要点：用 `pointer.getDuration()` 判断按住时长，用 `pointer.distance` 判断位移。进入框选模式后，把相机平移**锁死**，避免两个动作同时发生。

### 方案 B：点选 + 范围选择

- 点中一个单位 → 自动选中它周围同类的 5 个单位
- 想精确多选，用底部编组槽

优点：零学习成本，绝对不会误操作。
缺点：失去了精确控制，打不了微操。对"轻量 RTS"可以接受，对正经 RTS 不够。

### 方案 C：双指轻点 = 全选屏幕内单位

- 补一个"一键选全屏部队"的兜底

优点：极端简单。
缺点：只能当辅助，不能当主操作。

**我的建议：A 为主（长按框选），C 作为补充，再加 HUD 上两个按钮「全选部队」「全选农人」。** 三个入口覆盖 90% 场景，手指不用做精细动作。

## 下令：tap-tap 的坑和补法

选中单位后，点地面 = 移动。这看起来最自然，但有两个问题：

**坑 1：误触。** 玩家想点空地取消选中，结果部队跑过去了。

补法：**点击空白地面 = 取消选中，不移动**；要移动必须点在"有意义的区域"（地图内任意位置都算有意义……所以这条行不通）。

更实用的补法是**双保险**：
- 选中后，画面底部出现一个明显的"移动"激活态（选中的单位脚下有目标标记）
- 点地面下令后，目标点显示一个 **0.5 秒的落点标记**，期间点"取消"按钮可撤销

**坑 2：抬手才生效还是按下就生效？**

必须在 `pointerup` 时生效，不能在 `pointerdown`。手指按下时玩家还在调整，抬起的瞬间才是"确认"。Phaser 里就是 `this.input.on('pointerup', ...)`，你现在 `MainScene.ts:137-143` 用的就是 up，这点是对的，保留。

## 指令盘：什么时候值得做

长按单位 300ms 弹出环形菜单（移动/攻击/采集/驻守/取消）——RTS 手游常用。

**建议 v0.1 不做。** 理由：环形菜单在 5 英寸屏上按钮会挤到 40px 以下，误触率高于收益；而且你的玩法里单位类型少，用底部命令卡（一章 5 个按钮）已经够。

什么时候做：当单位指令超过 6 种，或者需要"对着某个目标下特定指令"（比如右键敌人=攻击、右键资源=采集）时。环形菜单真正的价值是**把"目标 + 动词"合并成一次操作**，而不是省按钮。

## 编队：用按钮，不用键盘

底部放 3-5 个编组槽（每个 56×56）：

- **点击** = 选中该编组
- **长按** = 把当前选中写入该编组
- **双击** = 镜头飞到编组位置

实现上就是 `groups: number[][]`（每组存单位 id），不复杂，但对手机玩家的体验提升极大——它替代了 Ctrl+1 到 Ctrl+5。

## 三段式操作链：在手机上完整走一遍

这是本作最关键的设计验证。按 `DESIGN-v2.md:5.5` 的核心循环，"农人 → 建造 → 祭祀"必须在手机上一条龙走通。我把它拆成手指动作：

### 第一段：选农人

1. 拇指点画面里的农人（命中区放大到 48px 半径）
2. 屏幕底部弹出**命令卡**（0.15s 上滑，占屏高 22%，约 160px）
3. 命令卡上是 5 个大按钮：耕作 / 伐木 / 采石 / 采玉 / 建造（每个 72×72，间距 16px）

注意：按钮**不要**放在屏幕最底部边缘，要留出安全区（`env(safe-area-inset-bottom)`），否则手势条会盖住。

### 第二段：建造

4. 点「建造」→ 命令卡展开为建筑列表（大邑 / 粟田 / 祭坛），每张卡显示造价与不可建造的灰态
5. 点「粟田」→ 进入**放置模式**：
   - 地图上出现半透明幽灵建筑
   - **不用手指拖**（手指会挡住建筑）。改为：手指在地图下方空白处拖动 = 平移地图；幽灵固定在屏幕中心，屏幕上显示"对准位置"
   - 底部出现「确认」「取消」两个大按钮
6. 点「确认」→ 农人前往施工，地块变灰（占用）

**这是手机 RTS 最容易被做坏的一步。** 桌面上"按住拖到位置松手"很自然，手机上手指一放就把目标挡住了。中心准星方案是所有手机 RTS 的标准解。

### 第三段：祭祀

7. 点祭坛 → 弹出祭祀面板（bottom sheet，占屏高 40%）
8. 面板里 3-4 个祭祀选项，每个显示：名称、玉的消耗、德望 +N 预览
9. 点选 → 面板收起，祭坛上出现读条与光效
10. 读条期间可以正常操作部队（不要锁全屏）

### 全链路的单手可达性检查

把手机横屏（RTS 必须横屏，竖屏视野太窄），屏幕高约 400-450 dp：

- 命令卡、祭祀面板：底部 0-40% → **拇指区**
- 资源条：顶部 0-8% → 只看不点
- 小地图：左下角 → 拇指区边缘，能点到但不碍事
- 战场：中间 → 手指主要活动区

如果某个高频按钮落在屏幕右上角，基本等于不可用。这是布局红线。

## 误触防护：五条具体规则

1. **拖动阈值**：位移 < 8px 视为点击，避免"手抖导致平移"。
2. **长按阈值**：250ms 进框选、300ms 弹指令盘。低于 200ms 会误触，高于 500ms 会觉得卡。
3. **不可逆操作二次确认**：拆除建筑、取消建造、解散编队，都要弹确认。
4. **取消区**：拖动过程中把手指拖到屏幕上方 1/5 区域 = 取消（类似 iOS 的"上滑取消"）。
5. **点击反馈**：任何点击必须有 ≤100ms 的视觉/震动反馈，否则玩家会重复点，产生"双指令"。

## 与现有代码的衔接

现在的输入代码基本要重写（`MainScene.ts:106-149`），但可以保留两个东西：

- `pointerup` 才结算的时序（`MainScene.ts:137`）
- 选择用世界坐标而非屏幕坐标（`MainScene.ts:142`）、框选用 `Phaser.Geom.Rectangle`（`MainScene.ts:201-209`）

需要新增的：

```ts
// 手势状态机，比一堆 if 清晰得多
type Gesture =
  | { kind: 'idle' }
  | { kind: 'pending'; startX: number; startY: number; downAt: number }
  | { kind: 'pan'; lastX: number; lastY: number }
  | { kind: 'box'; startX: number; startY: number }
  | { kind: 'pinch'; startDist: number; startZoom: number };
```

一个手势一个状态，`pointermove` 里按状态分发。这比"if 拖动 if 按下 if ..."可维护得多，也更容易在第 12 章做降级。

## 自检清单

在真机上（不是模拟器）逐条过：

- [ ] 单指点单位能选中，点空地能取消
- [ ] 单指拖空白能平移，不触发框选
- [ ] 长按空白 250ms 后拖动，能出选框，且此时画面不跟着动
- [ ] 双指能缩放，缩放后 UI 大小不变
- [ ] 选中农人 → 建造粟田 → 放置 → 确认，全过程单手可完成
- [ ] 放置模式下手指不会挡住幽灵建筑
- [ ] 命令卡按钮间距 > 12px，边缘按钮距屏幕边 > 16px
- [ ] 刘海/挖孔/手势条不遮挡任何按钮
- [ ] 连续快速点击 10 次不会出现"重复下令"

## 一句话总结

**桌面 RTS 的操作是"并行 + 精确"，手机 RTS 的操作是"串行 + 容错"。** 你要做的不是把右键换成别的键，而是把整条操作链重新切成手指能完成的步骤。
