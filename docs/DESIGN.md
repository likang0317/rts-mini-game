# RTS小游戏 设计文档（v0.1）

> 状态：方案草案，等待确认后再进入玩法实现。
> 技术栈：Vite + TypeScript + Phaser 3（2D），纯前端单页，无后端。
> 目标：一局 3～5 分钟、规则精简、可在浏览器直接玩的 1v1 即时战略小游戏。

---

## 1. 设计目标与边界

**要做的**
- 一张固定对称地图，玩家 vs 简单 AI，采集资源 → 造兵 → 推掉敌方基地。
- 完整的「选择 → 下令 → 交战」RTS 操作手感：框选、右键移动、右键攻击。
- 单页应用，打开即玩，无需登录、无后端。

**明确不做（MVP 阶段）**
- 不做战争迷雾、不做科技树、不做多资源、不做多人联机、不做地图编辑器。
- 不做建筑自由摆放（基地/兵营为固定点位建造，降低寻路与摆放复杂度）。

---

## 2. 核心玩法与胜负条件

| 项目 | 规则 |
| --- | --- |
| 对局形式 | 1v1，玩家（左下）vs AI（右上） |
| 单局时长 | 目标 3～5 分钟，M1 目标 2 分钟内可完成一次「采矿→造兵」循环 |
| 胜利条件 | 摧毁敌方「主基地」 |
| 失败条件 | 己方主基地被摧毁 |
| 平局处理 | 无（一方基地被摧毁即结束） |
| 资源 | 单一资源「晶石」；单位数量上限 20（不额外造人口建筑） |
| 战争迷雾 | 无（全员可见），M3 再评估 |

**节奏设计**：开局 100 晶石 + 1 基地 + 2 工人；前 60 秒以采矿和补工人为主，60～120 秒出第一批士兵，之后进入交战。

---

## 3. 操作方式

| 操作 | 行为 |
| --- | --- |
| 左键点击单位 | 选中单个单位（再次点击其他单位切换选择） |
| 左键拖拽 | 框选矩形范围内的己方单位 |
| Shift + 左键 | 追加/移除选择 |
| 右键点击空地 | 选中单位移动至目标点（简单队列，不绕障） |
| 右键点击敌人 | 选中单位攻击该目标 |
| 右键点击晶矿 | 选中的工人前往采集 |
| `A` + 左键 | 攻击移动（M2） |
| `S` | 停止当前指令 |
| `H` / `空格` | 镜头回到主基地 |
| `WASD` / 方向键 / 中键拖动 | 平移镜头 |
| 滚轮 | 缩放镜头（0.6x ～ 1.5x） |
| `Esc` | 取消选择 |

选中反馈：脚下青绿色选中圈 + 底部 HUD 显示选中数量与单位类型。

## 4. 资源与生产循环

```
工人 → 前往晶矿 → 采集（3 秒） → 返回基地卸货（+10 晶石） → 自动往返
                                              ↓
                                      晶石累积 → 基地训练工人 / 兵营造士兵 / 造炮塔
                                              ↓
                                        部队推进 → 摧毁敌方基地
```

- 初始资源：100 晶石。
- 晶矿：地图固定 4 处（双方各 2 处），MVP 视为无限储量，不显示剩余量。
- 单次搬运：10 晶石，单程约 3 秒；工人死亡则带走/损失已采集资源。
- 采集为「自动往返」，玩家只需右键点一次矿点，不需要逐个操作。
- 训练队列：每个生产建筑同时只能排 1 个单位，`Shift` 排队（M2 可选）。

## 5. 单位与建筑清单（精简版）

### 5.1 单位

| 单位 | 造价 | 生命 | 攻击 | 射程 | 移速 | 定位 |
| --- | --- | --- | --- | --- | --- | --- |
| 工人（Worker） | 50 | 60 | 5 | 近战 | 90 px/s | 采矿、建造，不主动作战 |
| 士兵（Soldier） | 60 | 120 | 12（1.2 次/秒） | 24 px | 110 px/s | 前排近战主力 |
| 枪手（Ranger） | 80 | 70 | 9（1 次/秒） | 140 px | 95 px/s | 后排远程输出（M3 开放） |

### 5.2 建筑

| 建筑 | 造价 | 生命 | 功能 |
| --- | --- | --- | --- |
| 主基地（Base） | —（初始自带） | 1000 | 训练工人、接收晶石、被摧毁即败 |
| 兵营（Barracks） | 120 | 500 | 训练士兵 / 枪手，需建在基地附近固定点位 |
| 炮塔（Tower） | 100 | 400 | 固定防御，射程 160，DPS 15 |

> 单位与建筑总数控制在 3 + 3，保证一个小游戏的内容量。

## 6. 地图与镜头

- 网格 40 × 30 格，单格 48px，世界尺寸 1920 × 1440。
- 布局：中心对称；玩家基地在左下 (8, 22)，敌方基地在右上 (32, 8)；双方基地附近各 2 处晶矿，中央 1 处争夺点（M3）。
- 地形：草地为基底，中间一条横向浅水带只做视觉分区，不阻挡移动（避免寻路）。
- 镜头：初始对准己方基地；`camera.setBounds` 限制在地图内；缩放 0.6x～1.5x，默认 1x。
- 移动：WASD / 方向键 / 中键拖动；无惯性、无边缘推屏（避免误触）。

```
┌──────────────────────────────────────────────────────────┐
│ 晶石 320   人口 8/20   时间 02:15          [设置]         │  顶部状态栏
│                                                          │
│                                                          │
│                      游戏世界（Canvas）                    │
│                                                          │
│                                                          │
│ ┌────────────────────────────────────────┐  ┌─────────┐  │
│ │ 选中：士兵 ×3   [移动] [攻击] [停止]    │  │ 小地图  │  │  底部指令栏 + 小地图
│ └────────────────────────────────────────┘  └─────────┘  │
└──────────────────────────────────────────────────────────┘
```

- 顶部状态栏：晶石数量、人口（当前/上限）、对局时间。
- 底部左侧：选中单位类型与数量、指令按钮（移动 / 攻击 / 停止）；选中工人时替换为建造按钮（兵营 / 炮塔）。
- 底部右侧：小地图（M2 加入）。
- 结算：全屏半透明遮罩 + 「胜利 / 失败」+「再来一局」按钮。
- HUD 使用独立 `UIScene` 叠加，不跟随镜头缩放。

## 8. 技术架构与目录结构

**分层原则**：数据与规则（`src/game`）不依赖 Phaser，场景层（`src/scenes`）只负责渲染与输入映射，方便后续单测与调平衡。

```
rts-mini-game/
├── index.html              # 挂载点 + 全屏样式
├── package.json
├── tsconfig.json
├── docs/
│   └── DESIGN.md           # 本文件
└── src/
    ├── main.ts             # Phaser.Game 配置与启动
    ├── scenes/
    │   ├── MainScene.ts    # 地图、单位、镜头、选择与移动（当前骨架）
    │   └── UIScene.ts      # HUD（M1 后期加入）
    └── game/               # 纯逻辑层（M1 起逐步填充）
        ├── constants.ts    # 地图尺寸、单位数值表
        ├── types.ts        # Unit / Building / GameState 类型
        └── systems/        # 采矿、生产、战斗、AI 系统
```

- 构建：`vite` 开发服务器；`tsc --noEmit && vite build` 产出静态资源，可直接托管到 GitHub Pages（仓库需转 public）。
- 状态管理：单一 `GameState` + `Phaser.Events.EventEmitter` 广播变更，HUD 订阅事件刷新。
- 渲染：地图网格用 `Graphics` 一次性绘制；单位用 `Rectangle` 占位（M1），M3 再替换为贴图精灵。
- 性能约束：60 FPS；单位上限 20；避免在 `update` 中创建对象。

## 9. 里程碑拆分

### M1 可玩骨架（当前阶段之后的第一步）
- 地图与镜头（平移 / 缩放 / 边界）
- 单选、框选、右键移动、停止
- 基地 + 工人 + 晶矿：采矿自动往返、晶石计入 HUD
- 基地训练工人（队列 1）
- HUD：晶石、人口、选中信息
- **验收**：能框选工人去采矿、攒够 50 晶石后在基地训练出新工人、全程无报错

### M2 战斗
- 士兵、兵营、炮塔；生命值、攻击冷却、死亡移除
- 右键攻击、自动索敌（攻击范围内自动开火）
- 简单 AI：按固定节奏造兵并周期性进攻
- 胜负判定与结算界面
- **验收**：一局完整 1v1 能分出胜负，AI 不会卡死

### M3 内容扩充
- 枪手（远程）、中央争夺矿点、小地图
- 数值平衡、音效、单位受击反馈
- 可选：战争迷雾、快捷键面板、移动端适配评估
- 可选：仓库转 public 并部署 GitHub Pages 试玩

## 11. 待确认的设计决策

1. 资源模型：单一「晶石」还是双资源？建议：单一晶石，降低上手成本。
2. 建造方式：固定点位建造还是自由摆放？建议：固定点位，避免 MVP 阶段做寻路与碰撞。
3. 单位数量：3 种单位是否够？建议：M1/M2 先用工人 + 士兵，M3 再加枪手。
4. 战争迷雾：是否需要？建议：MVP 不做，M3 再评估。
5. 美术风格：几何色块占位 vs 像素风？建议：先用色块，M3 统一替换为像素素材。
