# 03 触屏与适配：从“桌面稿缩小”到“手机上真的能玩”

> 这一章的前提很硬：本作的交付形态是 Android APK。手机不是“小一点的电脑”，触屏不是“没有鼠标的桌面”。如果 UI 只在 1920×1080 的浏览器里成立，它就没有交付。

## 为什么触屏是重设计，不是适配

桌面 RTS 的操作链是：**悬停看信息 → 左键选中 → 右键下令 → 滚轮缩放 → 键盘编队**。
手机上这五件事全部不成立：

- 没有悬停，手指按下才算事件。
- 没有右键，下令要拆成两步（选目标 → 点地面）。
- 拖拽已经被“平移镜头”占用。
- 没有滚轮，缩放靠双指。
- 没有键盘，热键提示是无效信息。

所以触屏 UI 的核心不是“把按钮放大”，而是**重新设计一条只用拇指就能走完的操作链**。

常见错误：把桌面 HUD 等比缩到手机上，然后说“字小一点而已”。实际是操作链断了。

## 1. 物理约束：手、眼、遮挡

### 1.1 三个尺寸

| 指标 | 经验值 | 说明 |
| --- | --- | --- |
| 手指接触面 | 9–11mm | 拇指比食指更宽 |
| 最小可点区域 | 44×44pt（iOS）/ 48×48dp（Android） | 低于这个值，误触率明显上升 |
| RTS 推荐按钮 | 56–64dp | 高频、连续点击、战斗中手抖 |

为什么：按钮尺寸不是审美，是命中率。RTS 的命令按钮会被连续快速点击，44dp 只是“能点”，56dp 才是“能打”。
常见错误：用 32–40dp 做图标按钮；按钮之间不留间距；把“关闭/撤退”做成小图标放在角落。

### 1.2 拇指可达区

手机横屏时，双手握持，拇指自然覆盖的是**屏幕左右下角**，不是整个底部：

```
┌──────────────────────────────────────────┐
│  顶部：只读（资源、任务、天气）            │  ← 远，难触达
│                                          │
│              战 场（主视野）              │
│                                          │
│  ┌────────┐                  ┌────────┐  │
│  │ 左拇指 │   中间：手挡住     │ 右拇指 │  │  ← 高频操作
│  │ 小地图 │                  │ 命令盘 │  │
│  └────────┘                  └────────┘  │
└──────────────────────────────────────────┘
```

推论：

1. **高频操作放左右下角**，不要放屏幕正中底部——手掌会挡住，而且左右手都够不到中心。
2. **顶部只放“看”的信息**，不要放需要频繁点的按钮。
3. **中间底部不要放关键按钮**，那是双手交叠、最容易被遮住的区域。

为什么：拇指的活动范围是一个以手掌为圆心的扇形，不是整个屏幕。
常见错误：把 5 个命令按钮横排在屏幕正下方中央；把“设置/撤退”放在顶部右角。

### 1.3 手指遮挡

手指按下去会遮住 1–2cm 的区域。规则：

- 关键信息（选中单位、目标、血量）不要放在按钮正上方。
- 按下时，按钮的反馈要出现在**手指上方或周围**，不要被手指盖住。
- 拖拽类操作（小地图、框选）要有“手指偏移量”，让内容出现在手指上方。

为什么：玩家看不见自己按了什么，就只能靠猜。
常见错误：把选中单位的信息放在命令按钮的正上方，拇指一按就挡住。

## 2. 手势与状态机

### 2.1 一张必须写清楚的状态表

触屏 RTS 的输入不是“事件”，是**状态机**。至少要定义：

| 手势 | 判定 | 结果 | 冲突 |
| --- | --- | --- | --- |
| 点按 | < 8dp 位移，< 250ms | 选中/确认 | 与拖动冲突 |
| 长按 | 250ms 不动 | 框选模式/查看信息 | 与点按冲突 |
| 拖动 | > 8dp 位移 | 平移镜头/拖小地图 | 与点按冲突 |
| 双指捏合 | 2 指 | 缩放 | 与平移冲突 |
| 双击 | 300ms 内两次 | 镜头聚焦/编队 | 与点按冲突 |
| 边缘滑动 | 距边 < 20dp | 交给系统（返回手势） | 与镜头平移冲突 |

为什么：没有状态表，程序会写出“有时候能选、有时候不能选”的玄学 bug。
常见错误：用 `touchstart` 直接下令，没有位移阈值；长按和拖动同时触发。

### 2.2 冲突的处理顺序

建议的优先级（从高到低）：

1. 系统手势（返回、通知栏）
2. UI 控件（按钮、小地图、命令盘）
3. 长按/框选
4. 拖动/平移
5. 点按/选中

为什么：系统手势不能让；UI 控件的意图最明确；战场手势可以兜底。
常见错误：全屏 `touch-action:none` 之后，Android 的返回手势失效，玩家被困在游戏里。

### 2.3 误触防护

- **扩大命中区**：视觉 40dp，命中 56dp（hit slop），不改变布局。
- **危险操作二次确认**：撤退、拆除、放弃祭祀。
- **可撤销**：建造落位后 1.5 秒内可取消。
- **防连点**：同一按钮 150–200ms 内只响应一次。
- **分隔危险按钮**：撤退/删除不要紧挨着攻击/确认。
- **触觉反馈**：`navigator.vibrate(10)` 用于确认/警告，不要每个按钮都震。

为什么：手机上误触一次的成本，可能是一整队兵跑进敌方基地。
常见错误：把“撤退”和“攻击”做成相邻的 48dp 按钮；没有撤销；按住不放连续触发。

### 2.4 触屏没有 hover

所有依赖 hover 的状态都要有替代：

| 桌面 | 触屏替代 |
| --- | --- |
| hover 看 tooltip | 长按查看 / 点选后显示 |
| hover 高亮 | 按下态（active） |
| 右键菜单 | 选中后底部命令盘 |
| 滚轮缩放 | 双指捏合 |
| 键盘热键 | 可见按钮 + 可选的外接键盘支持 |

为什么：hover 在触屏上不存在，写了也不会触发。
常见错误：设计稿里用 hover 表达“可点击”，程序上线后玩家完全看不到反馈。

## 3. 横屏 HUD 的重排

### 3.1 左右手分工

推荐：

- **左手**：小地图、镜头、选中/框选、编队。
- **右手**：命令、建造、祭祀、确认/取消。
- **中间**：战场，不放常驻按钮。

为什么：左右手各自形成一个“看—点”闭环，减少跨屏移动。
常见错误：所有操作都堆在右手，左手闲置；或者左右手都要跨到屏幕中心。

### 3.2 命令盘的三种形态

| 形态 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- |
| 网格（2×3 / 3×2） | 易扫视、易记位置、可放文字 | 占面积 | RTS 主命令，推荐 |
| 弧形/扇形 | 拇指行程短、有“手感” | 标签难排、位置难记 | 4–6 个高频动作 |
| 径向菜单 | 方向记忆强 | 学习成本高、遮挡战场 | 主机/PC，不建议手机 RTS |

本作建议：**右下 3×2 网格，56–64dp，图标 + 2–4 字标签**。建造/祭祀用二级面板从底部展开，不常驻。

为什么：RTS 的命令是“有名字的动作”，不是纯方向操作；网格的可读性和可记忆性最好。
常见错误：照搬主机游戏的径向菜单；按钮只有图标没有文字，玩家要背。

### 3.3 资源条放哪

三种方案：

1. **顶部通栏**：最省底部空间，但离拇指远；只读信息可以接受。
2. **左上角**：桌面传统；手机上要跨屏看。
3. **底部左角、小地图上方**：离拇指近，但占底部空间。

建议：**顶部左/中，紧凑图标 + 数字**；德望单独放在顶部或左下，不并进资源条。

为什么：资源是“看”的信息，不是“点”的信息；放顶部不占用拇指区。
常见错误：把资源做成底部一排大格子，每个格子 60dp，直接吃掉 1/3 的操作区。

### 3.4 小地图

- 尺寸：至少 120×90dp；再小就看不清兵点。
- 位置：左下，和资源同侧，形成“看资源 → 看小地图 → 点小地图”的闭环。
- 交互：点按跳转、拖动移动镜头、双指缩放（可选）。
- 比例：**必须和世界地图比例一致**，否则点击映射会错位。
- 视野框：正交俯视用**矩形**，不要用梯形。

为什么：小地图是 RTS 最高频的“看 + 点”组件，比例错了等于导航错了。
常见错误：小地图做成装饰图，比例和地图不一致；用梯形视野框，玩家以为镜头有透视。

## 4. 竖屏还是横屏

### 4.1 结论：RTS 优先横屏

理由：

- 战场需要宽度。竖屏 360dp 宽，放不下阵型和多单位。
- 双手握持横屏，左右拇指各有分工；竖屏只能单手握持，操作效率低。
- RTS 的信息密度高，竖屏需要上下堆叠 HUD，进一步压缩战场。

为什么：这不是习惯问题，是视野和操作面积的数学。
常见错误：为了“手机用户习惯竖屏”强行做竖屏 RTS，最后战场只剩一条缝。

### 4.2 如果必须竖屏

设计要点：

- 顶部：资源 + 德望（只读）。
- 中部：战场，镜头拉近，单位放大。
- 底部：命令盘 + 小地图（可折叠）。
- 单位卡纵向排列；一次最多 3 张。
- 提供“横屏提示”，但不强制。

代价：视野变窄、操作变慢、战场可读性下降。**个人判断：不值得为 RTS 做竖屏主模式。**

### 4.3 旋转与状态

- 锁定横屏（Android `screenOrientation="sensorLandscape"`）。
- 如果允许旋转：保持选中、镜头中心、未完成的建造落位；不要让旋转重置状态。
- 旋转后重新计算安全区和 HUD 锚点。

常见错误：旋转后 HUD 错位；建造 ghost 消失；镜头跳回基地。

## 5. 安全区与多分辨率

### 5.1 先算清楚手机的真实 CSS 视口

以 2400×1080 物理像素、DPR 3 的手机为例：

```
CSS 视口 = 2400 / 3 × 1080 / 3 = 800 × 360
```

如果 UI 按 1920×1080 设计再等比缩放：

```
scale = min(800/1920, 360/1080) = 0.333
96dp 按钮 → 32dp（低于 44dp 下限）
10px 文字 → 3.3px（不可读）
```

即使按 1920 宽、1080 高分别算，横向 scale=0.417，纵向=0.333，取小值仍是 0.333。**结论：固定 1920 画布在手机上不可用。**

正确的做法：**按 dp 设计，不按物理像素设计。**

- 基准：640×360dp（16:9 横屏最小可用区）。
- 扩展：19.5:9 / 20:9 多出来的宽度给战场，HUD 锚定边缘。
- 平板 4:3：多出来的高度给战场/面板，HUD 锚定边缘。

### 5.2 适配策略对比

| 策略 | 做法 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| 等比缩放 + 黑边 | 固定设计分辨率，`min(w/1920,h/1080)` | 实现最简单、构图不变 | 手机上字太小、黑边浪费 | 桌面/演示稿 |
| 锚点重排 | HUD 锚定四边，战场自适应 | 充分利用屏幕 | 需要每个组件写锚点 | 手机 RTS，推荐 |
| 分区适配 | 战场全屏，HUD 固定物理尺寸 | 操作手感稳定 | HUD 可能遮挡战场 | 手机 RTS，推荐 |
| 逻辑分辨率 + DPR | 以 dp 布局，按 DPR 渲染 | 字清楚、尺寸稳定 | 需要处理 DPR/性能 | 推荐底层方案 |

本作建议：**逻辑 dp 布局 + HUD 锚点 + 战场自适应 + 超宽屏把额外宽度给战场**。

为什么：RTS 的战场应该吃满屏幕，HUD 应该保持物理尺寸（拇指能点、眼睛能读）。
常见错误：用一套 1920 画布硬缩所有设备；用 `vw/vh` 写按钮尺寸，结果在平板上巨大、在手机上 tiny。

### 5.3 超宽屏的公平性

20:9 比 16:9 横向多出约 25% 的视野。在 RTS 里，这意味着“看得更多”，是实际优势。

处理方式：

1. **镜头高度固定**，多出来的宽度就是多看的范围（简单，但有优势）。
2. **限制镜头边界**，让超宽屏也只能看到固定战场宽度（公平，但两侧留黑/装饰）。
3. **按宽度缩放战场**，让所有设备看到同样的地图宽度（单位会变小）。

个人建议：单机/休闲对局用方案 1；如果做联机，必须用方案 2 或 3，并在设置里说明。

常见错误：不考虑超宽屏，导致 20:9 玩家能提前看到敌方，联机不公平。

### 5.4 安全区

Android 的刘海、挖孔、手势条会吃掉边缘。CSS：

```css
.viewport {
  padding:
    env(safe-area-inset-top)
    env(safe-area-inset-right)
    env(safe-area-inset-bottom)
    env(safe-area-inset-left);
}
```

HUD 的内边距建议：

```
inset = max(12dp, safe-area + 8dp)
```

横屏时重点看左右安全区（挖孔），竖屏看上下（刘海 + 手势条）。

为什么：不处理安全区，按钮会被挖孔遮住，或者被手势条误触。
常见错误：只测无刘海设备；用固定 20px 边距；把返回按钮放在手势条区域。

### 5.5 DPR 与渲染分辨率

- 逻辑尺寸用 dp，渲染尺寸 = dp × DPR。
- 低端机可以降渲染分辨率（0.75x/0.5x），但 UI 文字要保持清晰。
- Canvas/WebGL 的 `resolution` 不要盲目设 2 或 3；先测帧率。

为什么：UI 清晰度和帧率是一对矛盾，低端机上必须做取舍。
常见错误：为了“高清”把 DPR 拉到 3，结果中端机掉到 30fps。

## 6. 无障碍

### 6.1 色盲

- 约 8% 的男性有某种红绿色觉异常。
- 敌我不能只靠红/绿；加形状、图案、亮度差。
- 提供色盲模拟（ deuteranopia / protanopia / tritanopia）自检。
- 关键状态（中毒、增益、锁定）用图标 + 颜色双通道。

为什么：这不是“少数人”的问题，是 1/12 的男性玩家。
常见错误：红色 = 敌人、绿色 = 友军，其他完全一样；色盲模拟一开，战场变成灰色。

### 6.2 字号缩放

- 提供 80% / 100% / 120% / 130% 的 UI 缩放。
- 缩放后布局要重排，不能只是放大文字导致溢出。
- 最小字号不低于 11sp；关键数字不低于 14sp。

为什么：玩家年龄、视力、设备距离差异很大。
常见错误：只做“大/中/小”三档，实际只改字号不改布局，文字全溢出。

### 6.3 动效减弱

- 尊重系统 `prefers-reduced-motion`。
- 提供“减少闪烁/减少镜头震动”选项。
- 战斗中的高频闪烁（受击、警告）限制频率（≤3Hz）。

为什么：闪烁和镜头震动会引发不适，甚至光敏性癫痫。
常见错误：受击白闪每帧触发；胜利界面全屏闪烁。

### 6.4 单手与认知负荷

- 单手模式：把命令盘镜像到拇指侧。
- 菜单不超过两层；术语一致（“营造”不要一会儿叫“建造”）。
- 关键操作不设倒计时；战斗中的确认框要能暂停。

为什么：移动场景下，玩家可能只有一只手、注意力被分散。
常见错误：菜单三层嵌套；同一个东西三个名字；确认框在战斗中不暂停。

## 7. 本地化

### 7.1 文本会变长

经验值（相对中文/英文源文）：

| 语言 | 长度变化 | 风险 |
| --- | --- | --- |
| 中文 → 英文 | 字符数减少，但单词宽度增加 | 按钮变宽、换行 |
| 英文 → 德文 | +30% 左右 | 复合词超长 |
| 英文 → 俄文 | +30–50% | 按钮溢出 |
| 英文 → 法文 | +15–20% | 说明换行 |
| 中文 → 日文 | +10% 左右 | 字形差异 |

为什么：中文四字词很紧凑，英文/德文一个词可能比整句还长。
常见错误：按钮固定 96px 宽；标题只留一行；用图片做文字。

### 7.2 设计规则

- 文本容器用 `min-width` / `max-width` + 自动换行，不写死宽高。
- 按钮允许两行；超过两行就缩短文案或改用图标 + tooltip。
- 不把文字嵌进图片/图标；所有文案走本地化表。
- 字体要有回退栈；中文/日文/韩文分别指定字体。
- 数字、日期、单位用本地化格式；注意复数。

### 7.3 文化与符号

- 红色在中国是喜庆，在西方是危险；朱砂的语义要在目标市场验证。
- 龙、凤、玉璧在中文语境是正面符号；海外玩家可能只看到“装饰”。
- 图标避免手势、宗教符号、数字禁忌。

为什么：本作是文化题材，出海时“文化符号”既是卖点也是理解门槛。
常见错误：默认所有玩家都懂“德望”“受禅”；没有英文术语表。

## 8. 真机测试矩阵

至少覆盖：

| 维度 | 档位 |
| --- | --- |
| 性能 | 低端（4GB/入门 SoC）、中端、高端 |
| 屏幕 | 16:9、19.5:9、20:9、4:3 平板 |
| 异形屏 | 无刘海、挖孔、刘海 |
| 系统 | Android 10/12/15（按目标市场） |
| 输入 | 单手、双手、外接键盘（可选） |
| 设置 | 默认字号、最大字号、色盲模拟、减少动效 |

测试项：

- 拇指能否在不变换握姿的情况下点到所有高频按钮。
- 连续点击 20 次命令按钮，误触几次。
- 旋转/切后台/回来，状态是否保留。
- 安全区是否遮挡。
- 50 单位同屏，帧率是否稳定。
- 连续玩 30 分钟，是否发热降频。

## 9. 本章验收表

- [ ] 所有高频按钮 ≥56dp，低频 ≥48dp，间距 ≥8dp。
- [ ] 高频操作在左右下角拇指区，顶部只读。
- [ ] 没有依赖 hover 的状态。
- [ ] 点按/长按/拖动/捏合有明确阈值和冲突处理。
- [ ] 危险操作有确认或撤销。
- [ ] 横屏锁定；旋转后状态不丢。
- [ ] 按 dp 布局，不按 1920 画布等比缩。
- [ ] 处理 `safe-area-inset-*`，刘海/挖孔/手势条不遮挡。
- [ ] 超宽屏公平性有方案。
- [ ] 色盲模拟通过；有 UI 缩放；尊重减少动效。
- [ ] 本地化后按钮/标题不溢出。
- [ ] 至少 3 台真机、3 种分辨率验收。

## 常见错误总表

1. 把 1920 桌面稿等比缩到手机，字号只剩 3–4px。
2. 按钮 32–40dp，间距 0，战斗中疯狂误触。
3. 命令按钮横排屏幕正中，手掌挡住。
4. 依赖 hover 表达状态，触屏完全没有反馈。
5. 不做安全区，按钮被挖孔/手势条遮住。
6. 小地图比例和世界不一致，点击跳转错位。
7. 竖屏硬做 RTS，战场只剩一条缝。
8. 超宽屏不限制视野，联机不公平。
9. 红绿唯一编码，色盲玩家失去敌我信息。
10. 按钮固定宽，本地化后文字溢出。
