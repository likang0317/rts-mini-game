# 01 工具链：先定交付方式，再选软件

> 这一章不回答“哪个软件最强”，只回答一个问题：**以你现在的交付形态（Phaser 3 + Capacitor → Android APK，2D，独立开发），哪套工具组合能在最短路径上做出可运行、可迭代、不返工的 UI。**

## 为什么工具选择容易走偏

设计工具的营销话术都在比“功能多”和“效果炫”，但游戏 UI 的成本不在画出来的那一刻，而在**交付**：

- 设计稿里的高斯模糊、混合模式、图层样式，引擎能不能还原？
- 字体嵌进去之后，Android 上会不会变成另一种字形？
- 一个按钮有 6 个状态，程序能不能只改一个变量就切换？
- 半年后加一个“铜”资源，资源栏会不会整体重排？

所以下面所有判断都围绕五个维度：**产出物类型、上手成本、协作与交付、与引擎衔接的摩擦、授权与总成本**。功能清单只在它影响这五项时才提。

---

## 1. 先给结论

### 1.1 这个项目的推荐组合

| 环节 | 选择 | 理由 |
| --- | --- | --- |
| 主设计 / 规范 / 标注 | **Figma**（免费版够用） | 组件、变体、变量、自动布局最适合做“有状态的 HUD”；分享和评审成本最低 |
| 矢量精修 / 图标 / 离线 | **Affinity Designer** | 2025 年 10 月起整套 Affinity 免费；贝塞尔和路径运算够用，导出 SVG 干净 |
| 位图修图 / 材质 / 预烘焙 | **Affinity Photo** 或已有的 Photoshop | 只做“像素级”工作，不用它排版 UI |
| 像素画 / 序列帧 | **Aseprite** | 逐帧、洋葱皮、调色板、精灵表导出是同类里最顺的；买断价约 20 美元 |
| 交互动效 | **Rive**（状态机）或**引擎 tween** | 按钮/面板的多状态切换用 Rive；80% 的 UI 反馈直接用引擎 tween 更省 |
| 线性装饰动效 | **Lottie**（AE + Bodymovin） | 只做“播完就结束”的动效，如开场、结算、加载 |
| 3D 预渲染素材 | **Blender** | 只用来产出 2D 贴图/序列帧，不用它做 UI 布局 |
| 引擎侧 UI | **Phaser：DOM/CSS 覆盖层 + Canvas 战场内 UI 混合** | 与现有 `docs/ui/ui-a.html` 的 HTML/CSS 资产最接近，改造成本最低 |
| 图集 | **free-tex-packer** 或 TexturePacker | 免费方案足够；纹理多、需要压缩格式时再上 TexturePacker |

一句话：**Figma 做“决定”，Affinity 做“精修”，Aseprite 做“帧”，Rive 做“状态”，引擎做“最终 90% 的动效”。**

### 1.2 不推荐的做法

- 用 Photoshop 从零排版整个 HUD：改一个间距要动十几层，状态一多就失控。
- 用 Illustrator 画游戏内的纹理和光效：它是矢量工具，不是绘制工具。
- 用 After Effects 做按钮 hover / 禁用 / 冷却：这些是**状态**，不是时间线动画。
- 用 Blender 做 2D UI 布局：渲染一张背景可以，摆按钮是自找麻烦。
- 在 Figma 里画像素画：像素对齐、调色板、逐帧都不对路。
- 同时学五个工具：独立开发者最贵的是注意力，不是软件订阅费。

## 2. 逐个体检

### 2.1 Figma

**适合**：界面结构、组件与变体、设计 token、多人评审、给程序标注。做 HUD 这种“同一组组件反复出现、状态多”的东西，Figma 的组件/变体/变量是目前最顺的。

**不适合**：复杂位图绘制、像素画、逐帧动画、重度路径运算。

**上手成本**：有平面/前端基础的人 1–2 天能上手；真正难的是**组件抽象**，不是工具操作。

**协作与交付**：链接即评审，评论定位到像素；开发模式能看间距和色值。免费版可起步（文件数/版本历史有限），团队协作和完整历史需要付费席位，价格随区域和年付方式变化，以官网为准。

**与引擎的摩擦**：这是重点。

- 自动布局（Auto Layout）不等于 Unity 的 Layout Group，也不等于 Godot 的 Container；导过去通常要重排。
- 图层模糊、背景模糊、混合模式、内发光、噪点，在 UGUI/Canvas/Godot 里大多**没有等价物**，或者要写 shader。
- 阴影在 Figma 里是一个效果，在引擎里可能是一张九宫格贴图，或一个额外 draw call。
- 字体如果没嵌进引擎，设计稿里的宋体在 Android 上会回退成系统默认字体。

**结论**：主设计工具，首选。但要从第一天就遵守“**能在引擎里实现的效果才用**”的纪律。

### 2.2 Photoshop

**适合**：修图、合成、材质、笔刷绘制、预渲染贴图、把 3D 渲染结果修成 2D 素材。

**不适合**：UI 结构、组件复用、多状态管理、协作标注。

**上手成本**：低（大多数人本来就会），但“会用 PS”不等于“会做 UI”。

**交付摩擦**：切图靠图层命名和切片，状态靠图层组，改版靠手工同步；团队里最容易出现“设计稿和切图对不上”。

**授权**：Creative Cloud 订阅，单应用和全家桶价格不同，以官网为准。

**结论**：保留为**像素加工台**，不要当主设计工具。已有订阅就用，没有也不必为它单独付费。

### 2.3 Illustrator

**适合**：复杂矢量插画、标志、需要精确路径运算的图形、印刷级输出。

**不适合**：UI 排版、位图纹理、逐帧、交互状态。

**与 Affinity Designer 的关系**：两者能力高度重叠。AI 的优势是生态和印刷；Affinity 的优势是买断/现在免费、和 Photo/Publisher 一体、对个人更轻。**做游戏 UI 图标，两者都够，没必要同时学。**

**结论**：如果你已经在 Adobe 生态里，继续用；否则优先 Affinity Designer。

### 2.4 Affinity Designer

**适合**：矢量图标、UI 图形、路径精修、SVG 导出、离线工作。

**关键变化**：Canva 在 2025 年 10 月 31 日把 Affinity 整合为一个免费应用（Vector / Pixel / Layout 三个工作室），取消买断和订阅。桌面版已可用，iPad 版本按官方公告为准。这意味着它对独立开发者几乎没有授权门槛。

**与引擎的摩擦**：SVG 导出质量好，但要注意：

- 渐变、滤镜、图层效果在 SVG 里可能被栅格化或丢失。
- 文字要转曲，否则引擎端字体不一致。
- 画布尺寸和 viewBox 要统一到 24×24 或 32×32 的图标网格。

**结论**：矢量图标和图形的主力，尤其适合不想订阅 Adobe 的人。

### 2.5 Aseprite

**适合**：像素单位、建筑、道具、逐帧特效、精灵表。

**不适合**：高分辨率 UI 排版、矢量图标。

**上手成本**：低，但像素画的难点是“控制像素”和“调色板”，不是软件。

**交付**：直接导出 PNG 序列或 sprite sheet，配合图集工具；支持图层、标签、洋葱皮。

**授权**：官方买断约 20 美元；源码可获取，但“售卖编译后的二进制”受其 EULA 限制。学生/开源项目可按官方条款处理。

**结论**：如果本作走 32×32 像素/半像素路线，这是必备工具；如果全部走矢量/手绘，可以先用 Figma + 导出 PNG 顶一阵，但逐帧特效迟早需要它。

### 2.6 After Effects

**适合**：线性动效、合成、预渲染、复杂视觉特效、导出 Lottie 的源动画。

**不适合**：交互状态机、运行时参数控制、频繁改文案的 UI。

**隐藏成本**：AE 工程和引擎是两套时间轴；每次改时长、改颜色都要重新导出。团队里常见的“AE 里很好看，进游戏就变慢/变糊”多半是导出格式和分辨率没对齐。

**结论**：只在你要做 Lottie，或要做预渲染特效时使用；不要用它做按钮状态。

### 2.7 Lottie

**适合**：播完即结束的装饰动效、加载动画、开场、结算、图标的一次性强调。

**不适合**：需要根据游戏状态实时切换的 UI；需要复杂物理/粒子；需要大量文本动态替换的场景。

**为什么**：Lottie 的本质是“矢量关键帧播放器”，它擅长还原时间线，不擅长表达“如果资源不足就切换到禁用态，如果冷却中就走环形进度”。

**交付**：AE + Bodymovin 导出 JSON / .lottie；运行时库在 Web、Unity、Godot、Cocos 都有社区实现，但**跨端一致性需要逐个验证**。

**结论**：装饰动效可用；交互 UI 不要指望它。

### 2.8 Rive

**适合**：有状态、可交互的 UI 动效：按钮的 idle/hover/pressed/disabled、图标的状态切换、带参数的进度环、角色头像表情。

**为什么**：Rive 的状态机（State Machine）把“状态”和“过渡条件”放在文件里，运行时只传布尔/数值/触发器。设计端能直接表达“资源不足 → 禁用态”，而不是导出十段视频让程序自己切。

**与 Lottie 的差别**：Lottie 更偏“线性播放”，Rive 更偏“交互系统”。两者文件都不大，但 Rive 的运行时是独立的，需要确认目标平台的支持情况。

**代价**：多一个工具、多一个运行时、多一套调试方式；团队里只有一个人时，学习成本要算进去。

**结论**：如果 UI 状态多、你愿意多学一个工具，Rive 很值；如果状态简单，引擎 tween 更划算。

### 2.9 Blender

**适合**：3D 单位/建筑预渲染成 2D 精灵、背景、光照参考、法线/材质贴图。

**不适合**：2D UI 布局、图标、文字排版。

**与 UI 的关系**：它不是 UI 工具，但可以产出**UI 用的素材**：比如祭坛的等距渲染图、玉璧的高光贴图、胜利界面的背景。前提是你要接受“渲染管线 + 后期修图”的额外成本。

**结论**：需要 3D 质感素材时再用；纯 2D 矢量/像素路线可以完全不碰。

### 2.10 引擎侧 UI 系统

这一节只讲“和设计稿衔接时的真实摩擦”，不铺 API。

#### Unity：UGUI vs UI Toolkit

- **UGUI**：成熟、资料多、世界空间 UI 和复杂特效好做；但 Canvas 重建、图集管理、分辨率适配都要手工治理。适合“UI 元素需要和 3D 场景/粒子深度交织”的项目。
- **UI Toolkit**：UXML + USS，思路接近 Web，适合屏幕空间、数据驱动、大量列表/表单的 UI；运行时能力仍在演进。官方文档的定位是：屏幕覆盖层、跨分辨率、少纹理的 UI 优先 UI Toolkit；需要在世界空间定位/受光的 UI 优先 UGUI。
- **摩擦**：Figma 的 Auto Layout → UXML/USS 需要重写；Figma 的模糊/混合/阴影在 USS 里没有直接对应；字体、九宫格、图集仍要按 Unity 的规则来。

#### Godot：Control 节点

- **优点**：`Control` + 锚点/容器 + `Theme` 资源，做响应式 UI 很直接；`NinePatchRect` 处理面板拉伸；场景即组件，复用成本低。
- **摩擦**：没有官方 Figma 导入；SVG 导入是按固定尺寸栅格化，复杂矢量不如位图稳；字体、主题、动画要手工搭。
- **适合**：独立开发者、2D 项目、希望 UI 和场景在同一套节点树里管理。

#### Cocos Creator：UI 系统

- **优点**：`Widget` 对齐、`Sprite` 九宫格、`Label`/`RichText`、`Layout`，对国内 Android 渠道和原生打包友好；中文资料多。
- **摩擦**：设计稿到预制体主要靠手工；Figma 插件生态不如 Unity；复杂效果要靠自定义材质/Shader。
- **适合**：目标明确是 Android APK、需要接国内渠道 SDK、团队熟悉 Cocos 的情况。

#### Phaser（本仓库现状）

- **没有成体系的 UI 布局系统**：`NineSlice`、`Text`、`BitmapText`、`Container` 都要自己搭；但**可以直接用 DOM/CSS 做 HUD**，这对 `ui-a.html` 这种 HTML 稿是巨大优势。
- **摩擦**：Canvas UI 的字体、排版、遮罩、混合模式都不如 DOM 灵活；DOM UI 又要处理触摸穿透、层级、性能。
- **结论**：本作最现实的路线是“**战场内 UI 用 Phaser，屏幕 HUD 用 DOM/CSS，小地图用 Canvas**”的混合方案。第 05 章会给具体分工。

### 3.1 授权费用怎么算

不要只看订阅价，算“**总拥有成本**”：

```
总成本 = 软件费 + 学习时间 × 你的时薪 + 返工成本 + 协作摩擦
```

- Figma 免费版对单人足够；真正的成本是学组件抽象。
- Adobe 全家桶按月付费，适合已经靠它吃饭的人；独立开发者如果只是做图标，Affinity 免费后没有理由再为 AI 单独付费。
- Aseprite 的 20 美元是一次性的，半天就能回本。
- Rive 免费档能验证流程，团队协作/高级功能再付费。
- Unity/Godot/Cocos 的引擎本身不贵，贵的是“换引擎”的重写成本。

## 4. 三套组合，按你的阶段选

### 方案 A：零预算起步

```
Figma 免费版 + Affinity（免费）+ Aseprite（可选）+ Lottie + 引擎 tween + Blender（可选）
```

适合：先验证玩法和视觉方向，不买任何订阅。
代价：协作和版本管理弱；Rive 的高级状态机用不了，要用引擎 tween 自己写。

### 方案 B：独立开发者主推（本仓库）

```
Figma（免费或专业版）
+ Affinity Designer / Photo
+ Aseprite
+ Rive（免费档先验证）
+ 引擎 tween（主力）
+ free-tex-packer
```

适合：一个人负责设计 + 前端 + 打包 APK。
理由：这套组合里只有 Aseprite 是必须一次性付费的；其余都能免费开始。Rive 只在“状态确实复杂”时引入。

### 方案 C：小团队

```
Figma 组织版 + Adobe CC（动效/修图）+ Rive 团队版 + TexturePacker + Git LFS
```

适合：有专职美术、动效、UI 程序，交付节奏快。
代价：工具多、管线长，必须有 token 和组件规范，否则三个人会做出三套视觉。

## 5. 本项目的交付管线

### 5.1 从 token 开始，而不是从画布开始

在 Figma 里先建变量（颜色、字号、间距、圆角、描边），再建组件。导出时落成三层：

```
Figma Variables
   ↓（手工/插件导出）
design-tokens.json
   ↓（脚本生成）
tokens.css / tokens.ts
   ↓
引擎常量 + 组件样式
```

为什么：UI 一改色，程序不用全局搜索替换；三个阵营换肤只改变量，不复制组件。
常见错误：每个界面单独吸色，最后出现 7 种“差不多的金”。

### 5.2 图标

- 统一 24×24 viewBox，视觉安全区 20×20，1.5px 描边。
- 在 Affinity 里做路径运算，导出 SVG；需要多色时用 `currentColor`。
- Web/DOM 路线：内联 `<symbol>` + `<use>`，一个 sprite 文件搞定。
- Canvas/UGUI 路线：预栅格化为 1x/2x/3x PNG，打进图集；不要运行时解析 SVG。

为什么：SVG 在 DOM 里是矢量，清晰且可换色；在 Canvas/UGUI 里运行时栅格化会卡，且不同分辨率会糊。

### 5.3 面板与九宫格

- 面板底、按钮底、输入框底做成九宫格：四角不拉伸，中间拉伸。
- 导出时保留 2x/3x，九宫格边界用整数像素。
- 纸纹、噪点、渐变**预烘焙进贴图**，不要运行时用混合模式叠。

为什么：移动端 fill rate 有限，运行时模糊/混合/噪点是最容易把帧率吃掉的三个东西。

### 5.4 动效

| 类型 | 用什么 | 例子 |
| --- | --- | --- |
| 状态反馈（按下、禁用、选中） | 引擎 tween / CSS transition | 按钮按下 80ms、选中环 120ms |
| 数值变化 | 引擎 tween + 位图数字 | 资源 +20 的滚动/闪色 |
| 交互状态机（多状态互相切换） | Rive | 德望徽记的呼吸/将满/圆满 |
| 线性装饰 | Lottie / 序列帧 | 开场、结算、祭祀完成 |
| 战场特效 | 序列帧 / 粒子 | 命中、烟尘、血迹 |

为什么：把“状态”交给时间线工具，等于让程序用播放头做 if-else，改一次状态就要重导一次。

### 5.5 交付物清单

每个界面交付时至少包含：

1. 源文件（Figma 链接 / Affinity 工程）
2. 导出图（2x/3x，命名规范）
3. 状态矩阵（默认/悬停/按下/禁用/选中/冷却/不足）
4. token 引用表（用了哪些变量）
5. 动效说明（时长、曲线、触发条件）
6. 适配说明（最小宽度、横竖屏、安全区）
7. 真机截图（至少 2 种分辨率）

---

## 6. 常见错误

1. **把“会软件”当“会设计”。** 工具只决定效率，不决定判断。Figma 用得像 PPT，做出来的 HUD 仍然是平面海报。
2. **用位图工具做所有事。** PS 排 HUD，改一个间距要动十几层；状态一多必然失控。
3. **用时间线工具做状态。** AE 做 hover，程序只能播视频；改一个颜色要重导。
4. **设计稿用了引擎还原不了的效果。** 背景模糊、混合模式、内发光、噪点，在手机上不是“效果”，是“性能债”。
5. **不建 token。** 三个阵营三套金色，最后没人知道哪个是“主色”。
6. **每个图标一张纹理。** 手机 draw call 飙升，图集是必须的。
7. **只做 1920 桌面稿。** 手机横屏 CSS 视口可能只有 800×360，等比缩下去字号只剩 4px。详见第 03、06 章。
8. **把 AI 生成图直接当 UI 资产。** 风格漂移、文字错误、版权不明，后期修图成本高于自己画。
9. **同时学五个工具。** 先把 Figma + 引擎跑通，再按需加 Aseprite/Rive。
10. **没有“交付验收”。** 设计稿好看不等于引擎里能用；没有真机截图和状态矩阵，就不算交付。

---

## 7. 一页结论

- **主设计**：Figma。组件、变量、评审、标注，一项都不浪费。
- **矢量精修**：Affinity Designer。免费之后，独立开发者的默认选择。
- **位图**：Affinity Photo / 已有 PS。只做材质和修图。
- **像素/帧**：Aseprite。20 美元，别无二选。
- **动效**：引擎 tween 为主；复杂状态用 Rive；线性装饰用 Lottie。
- **3D**：Blender 只在需要预渲染素材时出现。
- **引擎 UI**：本仓库用 Phaser + DOM/CSS 混合；换引擎时，Unity 屏幕 UI 优先 UI Toolkit，世界空间/特效优先 UGUI；Godot 用 Control + Theme；Cocos 用 Widget + 九宫格。
- **真正的分水岭**：不是你会不会 Figma，而是你交出去的东西**能不能在手机上跑、能不能被程序低成本复用、能不能在半年后加一个新资源而不重排**。
